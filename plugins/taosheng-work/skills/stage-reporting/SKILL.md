# 阶段汇报机制

阶段完成或最终交付时，用一段人话说清：做成了什么、用户要不要动手、还有什么没做以及不做的后果、需要用户决定的事（选项写成后果）。技术证据放最后，不拿路径、提交号或测试数量代替结论。普通问答、只读核验、诊断和中间进度不套这个格式。

## 路由

1. **用户只想“以后阶段完成用人话汇报”**：读全局规则文件，看是否已覆盖“阶段完成时怎么汇报”的意思（按语义判断，不按标题）。
   - 已覆盖：告诉用户新会话自动生效，不改项目。
   - 未覆盖：把下面“推荐规则”给用户，请用户自己粘进全局规则文件，或在用户明确同意后由你写入。
2. **用户明确要求“严格拦截 / 兜底 hook / 漏了就自动重写”**：按“严格模式安装”给当前项目装 hook。
3. **诊断误拦或漏拦**：先把真实原句加进自己的回归语料，再做最小判据修改，不为单个例子堆正则。

## 推荐规则（可直接粘贴）

```markdown
## 阶段收尾汇报

- 仅在本轮实际完成明确阶段、里程碑或最终交付时触发。普通问答、只读核验、状态确认、诊断、方案讨论和中间进度不触发。
- 第一句同时说清做成了什么、要不要用户动手（没有就写“你现在不用做任何事”）。
- 然后按重要性列出还没做的事及不处理的后果、需要用户决定的事（选项写清后果），没有就不写。
- 只有解释用户不熟悉的技术机制时才打比方。
- 技术证据放最后，不用路径、commit 或测试数量代替结论。
```

## 严格模式安装（仅 Codex 项目，可选）

Codex 的 `Stop` 拦截会生成一条像新用户消息的 continuation，因此每次拦截会多一次生成。用户没有明确接受这一代价时不要安装。

1. 确认用户明确选择严格模式，且目标是当前项目；不要改全局 `~/.codex/hooks.json` 或全局 `AGENTS.md`。
2. 先看项目现有 `AGENTS.md` 与 `.codex/hooks.json`，保留其他规则和 hook。
3. 在本 skill 目录运行安装器：

```bash
python3 scripts/install.py <项目根目录>
```

安装器会：

- 在项目 `AGENTS.md` 中新增或更新带标记的“项目级严格阶段汇报兜底”；
- 新增或合并 `.codex/hooks.json` 的 `Stop` hook；
- 写入 `.codex/hooks/plain_stage_report.py`。

判据只有一份：`scripts/plain_stage_report.py`。改判据改这一份再重装，不要改项目里的副本。

## 验证

- 装完用 `python3 -m json.tool <项目>/.codex/hooks.json` 验证 JSON。
- `diff` 项目副本与 `scripts/plain_stage_report.py`，必须逐字节一致。
- Git 项目再跑 `git diff --check`。

## 告诉用户

严格模式只说三件事：装到了哪个项目；Codex 拦截会多一次生成；用户还需要在 `/hooks` 里审核并信任新 hook。不要替用户绕过 hook 信任。
