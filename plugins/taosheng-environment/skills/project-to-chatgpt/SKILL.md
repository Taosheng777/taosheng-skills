# 项目接入 ChatGPT

把用户指定项目加入现有“本地工作资料（只读）”，让 ChatGPT 读取当前事实源后分析。此 Skill 在 Codex 中执行接入维护；运行中的 MCP 提供资料。普通文件项目复用现有隧道、密钥和 7 个只读工具。

## 先确认当前事实

- 先运行 `python3 <本 skill>/scripts/manage.py registry list`，读取现有项目登记。连接状态用 `connection status`，不可将旧验收报告当成当前在线状态。
- 服务源码：`~/Documents/Codex/tools/local-work-mcp/`。固定配置、专用 Python、审计和连接状态在 `~/Library/Application Support/LocalWorkMCP/`。秘密值不进入 Skill、日志、回复或交付物。
- 优先从用户指定路径和当前本地索引定位项目，再按需读其 AGENTS、当前进度和入口文档。同一目录可能保留旧名称或旧分析；应把现行稿、现行结果和历史材料区分清楚，不凭修改时间独自判定最终版。
- 若用户只问是否值得接入，给判断即可；明确要求接入后持续执行。只在项目无法定位、范围/去向发生实质变化或工具权限要求时澄清。

## 确定并登记范围

在当前任务 work 下准备项目 JSON，字段和命令见 [接入操作](references/operations.md)。

- `id` 稳定唯一；`name` 用中文；`root` 仅为该项目根目录。
- 用 `include_paths` 明确选择文件和子目录；目录以 `/` 结尾，单文件精确匹配，不使用 glob。`exclude_paths` 优先于允许范围，不能被文档 ID 绕过。
- `status_files` 指向真实存在的当前入口，保留磁盘上的大小写，最多 8 份。首选能说明当前版本与未决事实的短文档；不要为接入强制改写源项目或制造“最终版”。
- 论文讨论通常选现行稿、补充材料、聚合表、分析代码和待补清单。不要顺带开放原始个体数据、全盘目录或备份；如用户明确需要更多材料，按该用途单独核对范围。医学资料的类型/用途/去向提醒沿用当前授权规则。
- 不把工具能力缺口伪装成读取成功。当前支持文本/代码、PDF、DOCX、XLSX 文本；图片不是视觉读取，PDF 不做 OCR，Word 不读取修订与批注，Excel 不重算公式。

执行登记预览，核对没有影响其他项目后，在当前授权范围内用 `--apply` 保存。脚本会备份配置、原子写入；重复应用同一配置不重复写入。不要把内部预览变成一律再问用户的审批流程。

## 验证并接通

1. 用 `probe` 对新项目做真实 stdio MCP 检查：列出项目、状态和文件，读取代表性原文并核对 SHA-256；至少验证一个明确排除的路径不可通过 ID 读取。源材料不得改写，项目分析脚本不得运行。
2. 配置在进程启动时加载。更新登记后需 `connection stop` 再 `connection start`，核对官方客户端 running/healthy/ready；同一隧道不得并行运行两个 stdio 实例。启动失败时从备份恢复配置并重启旧范围，避免破坏已有项目。
3. 使用现有 ChatGPT 插件。只新增项目配置、工具签名没变时，无需重建插件；若工具定义改变，再按实际界面刷新。插件描述需反映当前可用范围，不留“只读某一个旧项目”的错误说明。
4. 在用户账号的普通“聊天”里用其指定模型做一个有界真实查询。现有方案验证过 Chat 的 6 Pro；插件“在聊天中试用”可能进入 Work，应核对当前界面与模型，不擅自改用另一额度池。
5. 提示模型先 `list_projects` 再定位目标项目，读取指定当前稿/状态并引用路径、行号、SHA-256 和 read_at。对照本地原文与本地审计，确认答案来自本次读取。工具注册或本地健康检查不能代替这一步。

网页操作使用当前可用的原生浏览器能力；工具拒绝不绕过。登录或账号权限若确实阻塞，完成独立准备并说明最小解锁动作。既有授权不因换轮清零；新的权限扩张按实际工具要求处理。

## 交付与维护

给出已接入的项目名/ID、实际可读范围、真实查询结果、可直接使用的讨论提示词及仍需用户处理的事项。保存当前任务的证据与接力，避免把完整病例、账号或密钥写进通用 Skill。

日常文件保存后下次查询会读到新内容；新增接入范围需登记和重启；旧聊天答案不会自动改写。连接异常先检查现有实例、网络、密钥有效期，避免重复新建隧道或密钥。
