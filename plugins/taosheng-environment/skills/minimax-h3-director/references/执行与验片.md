## 一次批量审查

先验证 SSD。以下变量仅示范，实际视频和输出目录按当前项目替换：

```bash
python3 ~/.codex/skills/minimax-h3-director/scripts/gemini_review.py \
  '<你的工作目录>/Minimax视频/08-项目名/01-成片.mp4' \
  --out '<你的工作目录>/Minimax视频/08-项目名/过程文件/work/Gemini验片'
```

`--no-gemini` 仅本地技术扫描；`--prepare-only` 只生成拼图；`--force` 明确重审。同一视频内容和审查规格有完整缓存时复用报告。缺页、读图错误或 Gemini 失败不能算检查完成；保留已有输出，不自动循环。

脚本先测逐帧亮度与切点，再按间隔及切点抽样，并覆盖片尾；带时间码拼图一次交给 Gemini。它复用 `~/.agents/skills/gemini-dispatch/scripts/gemini_ask.py`；正常制作优先默认 `gemini-3.8-flash-high`。模型列表用 `agy models` 实时查，2026-10-26 本机已出现 Argon 三档，但本次未比较其审片质量，不自动改默认。

Gemini 只用读文件权限，结果由 Codex 落盘。账号调用串行，避免逐张独立请求的固定开销。不要照搬历史“约 1% 额度/5 分钟”为每次成本承诺。

## 问题表怎么处理

Codex 先读 `report.md`：输入文件、抽样范围、实际拼图数/自报读取数、时间码、问题、证据、置信度和未验证项。主控逐项决定“修、接受并说明、补局部证据”，不让 Gemini 独断审美。

- 技术脚本验证解码、帧数、尺寸、音轨、响度、哈希；自动黑段/渐变只是候选。只有时间线/剪辑决定才证明是有意设计。
- 缺页时补缺失范围；疑似穿帮时可把短段更密抽帧交给 Gemini。原版无变化时不重复扫整片；主控仅针对重要分歧看少量证据。
- 真实音频未送入支持音频的能力，就记录“未试听”。逐秒图不能证明连续动作、口型和瞬间缺陷全检通过。
- 技术扫描通过与模型报告无问题，都不替代作品约定的用户终审。交付时如实区分已完成制作、终审和发布。

DeepSeek 后续接入时先核实际可读格式、工具权限和费用；适合剧本备选/文字整理才派该类活，未验证前不宣称能替代 Gemini 看图。
