# 微信公众号文章检索

本地直连路径只用 Python 标准库。默认 `auto`：本机被搜狗或微信限流时，先改走普通搜狗网页索引；仍失败且环境里已有登录可用的 Firecrawl CLI 时，再自动用其远端出口完成同一项公众号检索和正文抓取。备用通道会消耗 Firecrawl credits，但不会改变用户的检索目标。

## 用法

```bash
python3 <skill目录>/scripts/wxsearch.py "关键词" --fetch 3 -o 输出目录
python3 <skill目录>/scripts/wxsearch.py "https://mp.weixin.qq.com/s/..." -o 输出目录   # 直接读一篇
```

| 参数 | 说明 |
|---|---|
| `--fetch N` / `-f` | 抓前 N 篇全文。默认 0，只出清单 |
| `--type` / `-t` | `article`（默认）或 `gzh`（搜公众号） |
| `--days N` / `-d` | 限最近 N 天 |
| `--page N` / `-p` | 翻页，每页约 10 条 |
| `--outdir` / `-o` | 输出目录，每篇一个 `.md` + `_results.json` |
| `--json` | JSON 到 stdout，便于程序化处理 |
| `--backend` | `auto`（默认）、`direct`（只走本地零依赖链路）或 `firecrawl`（强制远端验证） |

## 工作流程

**先不带 `--fetch` 跑一遍出清单**，看标题、公众号名和摘要判断哪几篇值得抓，再指定 `--fetch N`。这样比无差别全抓更省时间，也更少触发限频和消耗 Firecrawl credits。

`auto` 的固定顺序是：搜狗微信专用索引 → 普通搜狗中的 `mp.weixin.qq.com` 直达结果 → Firecrawl 抓同一个普通搜狗结果页。拿到文章后先本地抓正文，仅在微信拦截或本地网络失败时切 Firecrawl。Firecrawl 只是出口备用，不会把公众号文章请求替换成普通网页结果。

用户给了文章链接时，把链接直接作为参数传入，读取单篇全文：先本地直连，被微信拦截时（时拦时放，属正常）`auto` 改用 Firecrawl 抓同一链接，约耗 1 次 credits。

抓下来的 Markdown 带出处头（公众号、发布时间、原文链接），可直接归档。

## 汇报要求

向用户呈现结果时，**必须带上公众号名和发布时间**——这是判断内容可信度和时效性的关键，不能只给标题和正文。

## 内容可靠性（重要）

公众号文章是二手转述，用于专业场景时：

- **必须核对版本。** 医学诊断标准跨版本差异很大。实测遇到过标题写「诊断标准」、正文实为 DSM-IV（1994/2000）的文章，标题完全看不出来。引用前先在正文里确认版本号，拿错版本比没有更危险。
- **优先采信标了出处的。** 引了 PMID、期刊卷期的可信度显著更高；无出处的只当线索，不当依据。
- **不能替代一手来源。** 适合发现线索和获取中文解读，正式用途要回到官方手册、原始文献或临床指南。向用户交付时应说明这一点。

## 排障

**抓不到东西时，第一步永远是跑自检**，不要反复重试正常命令：

```bash
python3 <skill目录>/scripts/wxsearch.py --doctor
```

它只检查本地直连链路并发 2 个请求，其中「解析逻辑」一项是**离线**的，因此总能分清「工具坏了」和「本地 IP 被限流」。退出码：`0` 正常，`1` 工具/网络异常，`2` 本地直连被限流。`--doctor` 不消耗 Firecrawl credits；实际命令默认仍会尝试备用通道。

有两道**独立**的限流，症状不同，别搞混：

| 现象 | 原因与处理 |
|---|---|
| `--doctor` 报`搜狗反爬拦截` | **本地搜狗侧限流**。正常命令的 `auto` 会继续尝试普通搜狗和 Firecrawl；不需要重复撞专用接口。只有三路均失败才退出 2 |
| 本地搜索正常，但文章报微信拦截 | **微信侧独立限流**。`auto` 会改用 Firecrawl 抓同一篇原文；若 Firecrawl 未安装/未登录，才需要分批抓、拉大间隔或稍后再试 |
| 提示 Firecrawl 不可用 | 跑 `firecrawl --status` 检查安装和登录；不想使用 credits 时加 `--backend direct` |
| 某篇标记 `deleted` | 「该内容已被发布者删除」，正常情况，跳过即可 |
| 结果里没有想要的文章 | 覆盖面受限于搜狗索引，不等于微信「搜一搜」全量。换关键词或加 `--page 2` |
| `--days` 结果里有旧文 | 搜狗时间筛选是尽力而为，冷门词会用旧文补位。按结果的 `time` 字段自行过滤 |

**不要破解或提交任何验证码。** `auto` 使用独立的公开搜索/抓取出口；三路都被拦时停止并报告。

退出码：`0` 成功，`1` 一般错误，`2` 被限流拦截。

## 改动前必读

链路依赖三个易错点，改代码前先看 `README.md` 的「工作原理」：

1. **必须先访问搜狗首页建立完整 cookie 会话**（`ABTEST`/`SUID`/`SUV`）。只造 `SUV` 不够，跳转链会被 `antispider` 拦。
2. **逐级设置 Referer**：首页 → 列表页 → 跳转链 → 文章页。
3. **若改用浏览器自动化，必须用页内 `fetch()`，不能用导航。** 导航会触发 `location.replace` 跳微信，被判定爬虫并跳到验证码页，必然失败。
