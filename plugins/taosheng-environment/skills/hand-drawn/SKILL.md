# 手绘创作与逐笔视频

从观众需要看懂的内容出发，选择画法和时间组织。静态插画、插画上的人物动画、逐笔绘画是三个独立能力，按任务组合，不能互相冒充。

## 先决定什么值得画

动手前用几句工作记录说明：观众是谁；看完应理解或做到什么；最关键的因果、空间或时间关系是什么；画面如何让这段关系可见。已有材料能回答就直接推进，不固定访谈。

- 画一个对象，是为了让它与另一个对象发生可读的关系。装饰不能取代信息。
- 绘制顺序就是注意力顺序。先出现什么、何时补上变化、哪里停下来，都应服务于理解。
- 保留已认可的角色身份、事实和有效素材；复用方法不等于重复镜头。
- 工作量由信息密度和实际时长决定。页数、修正次数、配色数量和封面秒数不是普遍质量标准。

## 按交付选择路径

| 用户要什么 | 执行路径 |
|---|---|
| 仅讨论、分镜或技术方案 | 交付所需方案；明确“先规划／不渲染”时不启动生成和渲染 |
| 提示词或指定编号配方 | 读 [PROTOCOL.md](PROTOCOL.md)，输出文本或参考图调用包；不调用生成工具 |
| 新插画或改图 | 确定构图与参考图职责，用当前宿主图像能力；看实际图，针对缺陷修正 |
| 手绘板、白板或逐笔视频 | 先读 [制作约定与最终检查](references/制作约定与最终检查.md) 和 [逐笔视频制作](references/逐笔视频制作.md)；新生图再读 [绘制计划](references/生图前的绘制计划.md) |
| 多条作品或“太像了、重做” | 先读 [差异化设计](references/差异化设计.md)，改变叙事和画面组织，再制作 |
| 局部修改 | 只修受影响的图、时间线、声音或排版，检查由此改变的行为 |

画风有明确要求时遵从。只说“亲子”“手绘”不自动选 3.1，也不强制展示二十项菜单等待选择。根据内容选择一个有理由的方向并推进，只有会实质改变结果的缺项才澄清。清晰细线、适量点色适合路径描绘，但不是所有作品的固定画风。

21 套旧配方保存在 [STYLES.md](STYLES.md)，用 `python3 -B scripts/render_prompt.py --list` 查看。选中命名配方后使用完整模板和专属合同，不将其细节强加给其他画法。

## 把本次视频要求落实到制作

新制或重制视频先保存一份项目自己的制作约定：绘制方式、手部显示、声音、字幕、片长上限和必须看见的情节动作，以及这些选择的依据。已有明确要求直接沿用；缺省的普通选择由模型说明采用方案并继续，不要求重复确认。仅讨论、提示词和静态插画不进入这套视频检查。

以绘制过程为主体的手绘板/逐笔视频，未明确关闭时默认显示持笔手。明确无手或已有认可的无手方案照办。绘制手、角色的手与人物表演分别实现，不能互相替代；任务确定后不能以遮挡、方便合成为由静默关闭手部。

复杂原画先检验能否在实际时间内画清。编译后的笔迹必须做帧预算检查；数千独立笔迹不能压成几秒再称逐笔可辨。优先减少非必要纹理、合并属于同一连续笔画的路径、调整构图与分镜；加速绘画只能按任务明确的表现方式使用，不能为消除失败临时改名。

## 逐笔效果的可观察标准

- 轮廓沿独立路径生长；移到下一笔时抬笔，不画出连接无关部位的直线。
- 有持笔手时，真实笔尖持续贴合当前落笔处；按笔尖、手腕校准，手臂裁切边留在画外。
- 根据实际图像划分头、躯干、四肢、道具和遮挡，按语义安排轮廓与填色，不用矩形扫描整幅人物。
- 分区审查逐项对应当前图片、裁切和几何；矩形可以用于本来呈矩形的对象，复杂肢体须按实际边界和遮挡划分。剩余区说明实际内容，不能自动收纳未分好的主体；通用整图评语不能代替分区审看。
- 颜色随笔刷出现；完成局部后留出识别时间。持笔手不能挡住刚揭示的关键结果。
- 标题可逐字书写；字幕以可读为先。准确文字单独排版，字形近似描线不等于规范书法笔顺。
- 情节需要动作时，必须看得见起因、接触和结果。整图缩放不能证明角色已松手、转身或接住物体。

整体淡入、横向扫图、插画轻微摇晃可用于适当转场，不能单独作为逐笔效果的证据。

## 工具和声音由任务决定

先复用已有原画、准确声音和可运行引擎。已验证路线之一为 `threerocks/sweety-handdraw-video`，接入与限制见 [本地引擎](references/本地引擎.md)。引擎限制属于该实现，不成为用户需求。

声音可为现有配音、新配音、仅字幕配乐或无声，以当前任务为准。不指定固定供应商或音色，不把别的项目的声音偏好带入本片。新配音优先完成连贯的整篇旁白、核对后锁定母带，再以真实时间戳安排画面；已认可的声音和时间线直接复用。配音、字幕、尾音保护和局部修改见 [声音与字幕](references/声音与字幕.md)。字幕片先安排阅读时间。生成工具与大文件位置按当前宿主规则使用。

## 用输出验证

先检查能暴露主要风险的代表段，再完成整片。已明确授权制作时，这次内部检查不自动变成用户批准关卡；用户明确要求先审样片时遵守。

检查最终文件的画面、连续动作、文字和声音。抽帧、解码、ASR 与主观试听分别记录；自动通过不等于完整视听通过。改动后只重做受影响的检查。

定时时间线在构建前检查字幕重叠、实际字形宽高与音轨覆盖；最终文件可用 `scripts/media_checks.py 成片.mp4 --burned-captions --decode` 检查真实流和完整解码。该工具不能识别图片中烘焙的字幕或判断听感，检查范围须如实记录。

完整视频还必须经过 `scripts/production_checks.py`：把本次制作约定与**最终合成器实际使用**的时间线、字幕、声音和手部状态对应起来。只构建图片、给检查器传空字幕/无音频，不能验证有声成片。自写合成器可以使用，但须输出同样的最终记录并通过同一检查，不能沿用上游半成品的通过状态。

导出默认是待审看。运动证据来自连续片段；听感证据来自实际听音。检查记录绑定当前视频、最终合成记录与制作约定的哈希，旧版通过不得沿用。工程通过、待审看、审看失败和审核通过分别报告；做不到的检查保留缺口，不自动填通过。具体格式和复核命令见 [制作约定与最终检查](references/制作约定与最终检查.md)。

静态交付给图和必要提示词；视频交付可播放文件、所需字幕与复跑入口。任务专用的包装、机构身份和投递条件保留在项目材料里，不转为本技能的默认内容。
