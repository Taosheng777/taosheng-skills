# 从本次要求检查到最终视频

用于新制、重制和会改变表现方式的视频修订。它把要求与实际合成对应起来；不替用户决定创意，不替模型看图或听音。静态图、提示词、讨论不需要这些文件。

## 一份项目约定

从当前对话、已认可方案和项目事实直接整理，缺省选择说明依据后推进。已有明确要求不用再问；不得把模型默认写成用户确认。例子中的声音和动作按本片替换，不作为通用内容。

`制作约定.json`：

```json
{
  "version": 1,
  "drawing_mode": "traceable",
  "hand": "visible",
  "audio": "narration",
  "captions": "burned",
  "max_duration_seconds": 90,
  "decision_basis": "记录本次真实指令、已认可选择及模型补足的默认方案",
  "required_actions": [
    {"id": "handover", "observable": "接收者接住物体后，原持有人松开手"}
  ]
}
```

- `drawing_mode`：`traceable` 为逐笔可辨；`timelapse` 为明确选择的加速绘画；`illustration_motion` 为插画动画。切换表现方式要有真实任务依据，不能为通过检查临时降级。
- `hand`：`visible` 或 `hidden`。逐笔视频缺省 visible；用户明确无手、已有认可无手或插画动画方案按实际选择。后续合成遵守该值。
- `audio`：`narration`、`music`、`none`。`captions`：`burned`、`soft`、`none`。无声与无字幕是合法路线；有声或有字幕任务不能用空输入通过检查。
- `max_duration_seconds` 包含片尾；无明确上限可省略。`required_actions` 写本片必须呈现的变化；确无情节动作时可为空，不为凑数添加。

约定保存在项目。需修改时先说明变化依据，并重新检查受影响产物，不重签旧审查冒充新结果。

## 分区与帧预算

复杂插画先以 `render_timeline.py build --assets-only` 准备分区与路径，所有输出仅为资产。`work/timeline.json` 和 `work/drawing-check.json` 可用于诊断；不证明完整视频可交付。

```sh
python3 scripts/drawing_checks.py audit /任务/work/timeline.json
python3 scripts/drawing_checks.py preview-parts /任务/work/timeline.json --output /任务/work/分区预览
python3 scripts/drawing_checks.py parts-hashes /任务/job.json
```

查看真实原图、分区预览及必要遮挡。矩形对书页等对象可以合理，不能用统一方框切复杂人体，也不能用全图剩余区掩盖漏分主体。预览只淡化未选区域；不改变原图，不自动填写语义结论。

在每个 illustration 动作中记录 `part_review`，其 observations 的键须与 parts 的全部 id 一一对应：

```json
{
  "part_review": {
    "geometry_sha256": "parts-hashes 输出的本动作实际哈希",
    "status": "pass",
    "observations": {
      "head": "实际看到的头部边界，以及哪些交叉像素归属背景或道具",
      "prop": "实际看到的道具轮廓与握持接触边界"
    }
  }
}
```

这里只展示格式。没有看过不能填写 pass；源图、裁切、parts 或 white_key 变化后旧记录失效。脚本检查对应关系，不证明这些文字属实或分区正确。

帧预算按最终 fps 和落笔窗口计算，统计独立轮廓笔画、上色笔刷经过次数及移笔。一个笔画内的折线控制点不是多个笔画。独立落笔数量大于该窗口的帧数时，逐笔路线拒绝继续；这是“一帧只能显示一个主笔位置”的必要下界，绝非自然度标准。没有落入采样时刻的短笔迹另作提示，须在代表段检查跳笔、突然补色和同时显现。

先减少无叙事作用的碎纹理，合法合并同一条连续线，增加笔刷覆盖或调整画面分工；不能把断开的笔画强连起来、提高检测容忍度、拉快旁白或超出用户时长。加速绘画仍保留密度报告，以相应名称验收。

## 检查必须用最终合成数据

完整定时任务在 `job.json` 设置 `"contract":"制作约定.json"`。普通 build 检查完整字幕/声音设置、逐项分区记录和帧预算；完整 render 在编码前复查，编码后自动检查实际成片，并写 `outputs/composition.json` 和 `outputs/production-check.json`。默认结果为 `needs-review`。

`--assets-only` 仅用于 build。资产时间线可抽帧或导出明确的诊断预览，不能当作完整视频导出；预览的 scope 为 preview。旧任务可以读取与诊断，完整重制时按当前约定迁入，不能批量补写通过。

自定义合成器同样输出最终合成记录，必须使用其**实际采用的最终数据**，覆盖缩放、重新定时、字幕、音轨和手部图层接入后的状态，不能只拷贝上游原始开关：

```json
{
  "version": 1,
  "contract_sha256": "制作约定文件实际SHA-256",
  "video_sha256": "最终MP4实际SHA-256",
  "input_hashes": {"实际使用的素材、声音、字体与合成代码路径": "各文件实际SHA-256"},
  "renderer_files": ["实际最终合成代码路径"],
  "composition": {
    "scope": "final_video",
    "duration": 60,
    "canvas": {"width": 1920, "height": 1080, "fps": 30},
    "hand_visible": true,
    "action_windows": {"handover": [25, 29]},
    "captions": [{"start": 1, "end": 3, "text": "实际字幕"}],
    "audio": {"source": "实际完整混音.wav", "start": 0},
    "assets": {},
    "pages": []
  }
}
```

assets/pages 必须填入实际绘制事件，结构同定时时间线：事件引用 asset，start/end 为最终绝对秒数；asset.segments 的 start/end 为该事件内 0..1，每段 kind 为 ink/color/travel。静态排字用 role=static 或 caption=true，不伪造笔迹；不能把本应绘制的主体改标静态以消除错误。插画资产保留 drawing_input（source_sha256、crop、parts、white_key、part_review），并将实际 source 绑定到 input_hashes。图片经最终裁切或遮挡后仍需审看关键结果。

action_windows 与制作约定的 required_actions 一一对应，填写每项动作在最终视频中的真实呈现起止时间；没有必需动作时可省略或用空对象。定时入口读取 job.json 的同名字段。renderer_files 列实际最终合成器及必要运行代码，并纳入 input_hashes。

这些空 assets/pages 是格式示意，逐笔成片会被拒绝；不能将示意中的假哈希或字幕用于真实产物。所有相对输入路径相对 composition.json 所在目录。没有音频时 audio=null，没有字幕时 captions=[]。

```sh
python3 scripts/production_checks.py --contract /任务/制作约定.json \
  --assembly /任务/outputs/composition.json --video /任务/outputs/film.mp4 \
  --bin-dir /已有FFmpeg目录
```

工具核对实际视频哈希、画幅、fps、时长、流、完整解码、音轨覆盖、输入新鲜度、字幕时间及绘制预算。`hand_visible=true` 仍只是合成器记录；是否真的显示、笔尖是否跟随以及字幕是否烘焙重复，必须看实际成片。

## 审看记录不能自动生成通过

`review.json` 绑定当前 video_sha256、assembly_sha256、contract_sha256，并在 checks 下记录真实观察：

```json
{
  "video_sha256": "实际哈希", "assembly_sha256": "实际哈希", "contract_sha256": "实际哈希",
  "checks": {
    "visual": {"status":"not_checked", "evidence":"", "intervals":[]},
    "drawing": {"status":"not_checked", "method":"continuous", "evidence":"", "intervals":[]},
    "hand": {"status":"not_checked", "method":"continuous", "evidence":"", "intervals":[]},
    "part_semantics": {"status":"not_checked", "evidence":"", "intervals":[]},
    "speech_content": {"status":"not_checked", "evidence":"", "intervals":[]},
    "listening": {"status":"not_checked", "method":"listened", "evidence":"", "intervals":[]},
    "action:handover": {"status":"not_checked", "method":"continuous", "evidence":"", "intervals":[]}
  }
}
```

按任务自动确定所需检查，无声片无需听音，无手片无需手部审查，原生路径无需图片分区审查。实际审看后填 pass/fail、具体看到了什么及 [开始秒数,结束秒数]；运动需要连续片段，静态抽帧不能代替。listening 的 listened 表示实际完整听过，时间范围要覆盖全片；ASR可以用于 speech_content，不能当听感。所有关键场景和 required_actions 要有证据，不能只看开头就推定后面都成立。

检查器核对覆盖范围：visual 每个页面至少有观察，drawing/hand 覆盖每个实际落笔窗口，action:id 覆盖相应 action_windows；speech_content 与 listening 覆盖全片。记录可以分成多个真实片段，不能用“看过开头”填成全片通过。插画动画允许并行图层，不套用逐笔路线的一支主笔时序；只有移笔没有落笔不能冒充绘画。

复查时在上面的命令追加 `--review /任务/review.json`。退出码：0=所需记录齐全且各项通过；2=工程失败、过期或审看失败；3=待审看。缺少审听能力时如实交付待审看结果，不能伪造记录、无限重渲染或把退出码3当编码失败。审核通过仍不等于上传、发布或报备。

源文件版本绑定只能防过期与误接线，无法阻止故意绕过脚本或虚构观察。维护 Skill 时需另用现实请求检查模型有没有实际遵循流程，不能用单元测试数量替代这项验证。
