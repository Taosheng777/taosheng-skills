### 3.7 行业板块排名（V3.0 改用东财 — 同花顺加了反爬401）

东财行业板块涨跌幅排名，一次调用看全市场行业轮动。

生产入口为 `scripts/industry_ranking.py` 的 `industry_comparison(top_n=20, trade_date=None)`。先把本 skill 的 scripts 目录加入 Python 模块路径，再导入：

```python
from industry_ranking import industry_comparison
# trade_date 省略时要求中国时区当天；历史或非交易日必须显式给出交易日。
data = industry_comparison(20, trade_date="2026-09-21")
print(data["trade_date"], data["source"], data["total"])
print(data["top"], data["bottom"])
```

- 优先读取**指定日、东财行业分类、具有完整截面凭证**的本地 SQLite 快照。在线失败也可回到该缓存，不取旧日顶替、不拼接 THS 分类。
- 缓存没有上涨/下跌家数及领涨股，返回 `None` 并列入 `missing_fields`；只完成全市场价格排名，不冒充板块宽度已核验。
- 无合格缓存时经共用 `em_get()` 串行分页，核对总数、重复代码、缺页、数据日和数值，再全量排序。`bottom` 是全市场末列，不能再拿第一页100条的末尾冒充跌幅榜。
- 完整收盘同步成功后才登记 `snapshot_coverage` 凭证。旧库不能仅凭行数猜完整；一次性迁移须有同日完整同步成功回执，核对数据库路径和行数后登记来源证据。
- 无法取得完整结果时抛明确异常，不返回空榜或部分排名。`prefer_cache=False` 可要求先取在线明细，失败回缓存时显式记录缺字段。

### 3.8 板块资金流向（行业/概念/地域 × 今日/5日/10日）

东财板块资金流向——主力净流入额/净占比 + 超大/大/中/小单四档，覆盖行业、概念、地域三类板块，今日/5日/10日三个周期。与 §3.7 板块排名**同源同接口**（push2 `clist`），只是补请求了资金流字段（`f62/f184/f66...`）。走 `em_get` 限流防封。

```python
import requests

# 板块类型 → 东财 fs 参数
_BOARD_FS = {"industry": "m:90+t:2", "concept": "m:90+t:3", "region": "m:90+t:1"}
# 周期 → (排序fid, 主力净额, 主力净占比, 涨跌幅, 领涨股name)；四档明细仅今日
_BOARD_PERIOD = {
    "today": ("f62",  "f62",  "f184", "f3",   "f204"),
    "5d":    ("f164", "f164", "f165", "f109", "f257"),
    "10d":   ("f174", "f174", "f175", "f160", None),   # 10日领涨股名称字段不稳定，省略
}

def board_fund_flow(board_type: str = "industry", period: str = "today",
                    top_n: int = 20) -> dict:
    """
    板块资金流向排名（按主力净流入降序）。
    board_type: industry(行业) / concept(概念) / region(地域)
    period:     today(今日) / 5d(5日) / 10d(10日)
    返回: {board_type, period, total, rows:[{rank, name, code, change_pct,
           main_net(主力净额,元), main_pct(主力净占比,%), leader(领涨股),
           # 仅 today：super_large_net/large_net/medium_net/small_net(超大/大/中/小单净额,元)}]}
    注：板块级只有 今日/5日/10日（无 3日，个股级才有）。主力净额 = 超大单 + 大单。
    """
    if board_type not in _BOARD_FS:
        raise ValueError(f"board_type 须为 {list(_BOARD_FS)}")
    if period not in _BOARD_PERIOD:
        raise ValueError(f"period 须为 {list(_BOARD_PERIOD)}")
    fid, f_main, f_pct, f_chg, f_leader = _BOARD_PERIOD[period]

    fields = ["f12", "f14", f_chg, f_main, f_pct]
    if f_leader:
        fields.append(f_leader)
    if period == "today":
        fields += ["f66", "f72", "f78", "f84"]   # 超大/大/中/小单净额

    url = "https://push2.eastmoney.com/api/qt/clist/get"
    params = {
        "pn": "1", "pz": "200", "po": "1", "np": "1",
        "fltt": "2", "invt": "2", "fid": fid,       # fid + po=1：按该周期主力净额降序
        "fs": _BOARD_FS[board_type],
        "fields": ",".join(dict.fromkeys(fields)),  # 去重保序
    }
    r = em_get(url, params=params, headers={"User-Agent": UA}, timeout=15)
    items = r.json().get("data", {}).get("diff", []) or []   # 注：API 的 total 字段不可信，用 len(items)

    rows = []
    for i, it in enumerate(items):
        row = {
            "rank": i + 1,
            "name": it.get("f14", ""),
            "code": it.get("f12", ""),
            "change_pct": it.get(f_chg, 0),
            "main_net": it.get(f_main, 0),          # 主力净流入净额（元）
            "main_pct": it.get(f_pct, 0),           # 主力净流入净占比（%）
            "leader": it.get(f_leader, "") if f_leader else "",
        }
        if period == "today":
            row.update({
                "super_large_net": it.get("f66", 0),
                "large_net":       it.get("f72", 0),
                "medium_net":      it.get("f78", 0),
                "small_net":       it.get("f84", 0),
            })
        rows.append(row)

    return {"board_type": board_type, "period": period,
            "total": len(rows), "rows": rows[:top_n]}

# 用法
d = board_fund_flow("industry", "today", 10)
print(f"行业板块今日主力净流入 TOP{len(d['rows'])}（共 {d['total']} 个）:")
for r in d["rows"]:
    print(f"  {r['rank']}. {r['name']}: 主力 {r['main_net']/1e8:.2f}亿 ({r['main_pct']}%) "
          f"涨跌{r['change_pct']}% 超大{r['super_large_net']/1e8:.2f}亿 领涨{r['leader']}")

# 概念板块 5 日资金流
concept_5d = board_fund_flow("concept", "5d", 10)
# 地域板块 10 日资金流
region_10d = board_fund_flow("region", "10d", 10)
```

#### 板块逐日资金史（V3.5.4，2026-08-13）——缓存是生产事实源

**发现结论不变**：东财 `push2his fflow/daykline` 对 `90.BKxxxx` 确实返回板块逐日主力资金、四档净额、净占比、板块指数收盘点位与涨跌幅，解锁连续 N 日回溯、MA/z 分数、死亡条件误报回测和退潮 T+N 复核。

**生产访问方式已改变**：该历史路径存在强路径级风控，重复请求会放大故障。禁止在复盘、冒烟测试或全板块任务里逐板块直连它；统一走 `scripts/board_fund_flow_cache.py`。

| 顺序 | 数据层 | 规则 |
|---|---|---|
| 1 | 本地 SQLite | 默认读取；按 `eastmoney_dc + BK代码 + 交易日 + provider` 留存来源 |
| 2 | 东财 `push2delay clist` | 每日收盘后分页抓全行业/概念/地域的当日值，校验 `total` 与 `f297` 后增量入库 |
| 3 | Tushare `moneyflow_ind_dc` | 可选历史补洞；与东财 DC 同分类，需 `TUSHARE_TOKEN` 和对应积分权限 |
| 4 | 东财 `push2his` | 最后补洞源；**只发一次**，失败即持久熔断，不重试、不轮换代理、不换域 |

默认数据库：

```text
~/Library/Application Support/a-stock-data/board_fund_flow.sqlite3
```

可用 `A_STOCK_DATA_HOME` 改目录。token 只从环境变量读取，不写入数据库、日志、配置或命令输出。

**每日收盘增量：**


```python
    "BK1591",
    lmt=120,
    provider="cache",
```

`end_date` 是强 Gate：缓存即使已有 120 行，只要末日不是指定交易日，也抛 `InsufficientHistoryError`，不得用陈旧窗口判“未触发”。跨源同日数字超过容差时抛 `DataConflictError`，不得静默选边。

JSONL 每行格式为 `{"code":"BK1591","name":"...","rows":[[日期,主力净额,主力净占比,收盘点位,涨跌幅],...]}`；重复导入幂等，重复板块/日期自动去重并报告，内容不一致则拒绝覆盖；结果同时返回源文件 SHA-256。导入后仍应通过每日快照接续新交易日。

**Tushare DC 补洞（先审计、后回填）：**

```bash
export TUSHARE_TOKEN='由用户在当前环境配置'
# 只有使用明确授权的兼容端点时才设置；默认不设，走官方 API
export TUSHARE_HTTP_URL='https://example-compatible-endpoint.invalid'

# 只读 Gate：至少 115 个重叠交易日，检查方向翻转与决策级偏差
python3 ~/.codex/skills/a-stock-data/scripts/board_fund_flow_cache.py \
  audit-tushare --start-date 2026-02-11 --end-date 2026-08-13 \
  --anchors BK1137 BK1591 --minimum-overlap 115

# Gate 通过后按交易日补洞；支持中断续跑，永不覆盖已有板块日期
python3 ~/.codex/skills/a-stock-data/scripts/board_fund_flow_cache.py \
  backfill-tushare --start-date 2026-02-11 --end-date 2026-08-13 \
  --types industry concept region --anchors BK1137 BK1591
```

Tushare 的 `moneyflow_ind_dc` 返回 DC 板块代码、逐日 `close`、`net_amount` 和四档资金，属于可对账的同分类替代。官方说明见 [moneyflow_ind_dc 接口文档](https://tushare.pro/document/2?doc_id=344)。`moneyflow_ind_ths`、`moneyflow_ind_dc` 以外的 THS 行业/概念接口是**另一套分类体系**，不得拼接进既有 `BKxxxx` 死亡条件序列。

回填的安全边界：只写主库完全缺失的 `board_code + trade_date`，既有东财值即使与 Tushare 有微小差异也不覆盖；检查点按 `类型范围 + 交易日` 保存，可安全续跑。源端 `close=0` 行写入 `backfill_rejections` 留痕但不进入行情表。历史源若短暂错标板块类型，以最近完整 `clist` 快照的单值目录为准，只校正分类字段，不改任何行情值。

**故障与熔断纪律：**

- `push2his` 一次返回空 `klines`、连接重置、超时或 HTTP 错误，统一记为“源不可达”，写入 SQLite 熔断状态；冷却窗口内后续调用不发网络请求。
- `--force-probe` 只供明确的人工诊断；正常任务禁止绕过熔断。
- `push2delay` 对 `fflow/daykline` 返回 HTTP 200 + 空表，不是历史备胎；这里只把它的稳定 `clist` 用作**当日全板块增量**。
- 个股资金流按成分股相加只能得到派生代理：概念成分会重叠、历史成分会变、供应商的大单口径也未必一致。没有点时成分与同口径验证时，不得替代 DC 原始序列，更不得用市值加权伪造板块主力净额。
- 请求行数不足、指定末日缺失或多源冲突时，一律写“本项未验证”，绝不能默认判为“未触发”。
